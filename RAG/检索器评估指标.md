- **高**：几乎所有 RAG 评估必选，直接反映系统核心短板（检索首位命中、答案忠实度、覆盖度等）。
- **中**：特定场景（如排序精细度、多级相关性、生成答案与真值对比）需要，或有替代指标可部分覆盖。
- **低**：高级诊断、特殊需求（如极低延迟要求）或学术研究时才使用。

| 指标                     | 类别    | 评估对象     | 核心问题                    | 准确释义                                | 重要度                      |     |
| ---------------------- | ----- | -------- | ----------------------- | ----------------------------------- | ------------------------ | --- |
| **Hit@1**              | 检索器效果 | 检索器      | 排第一的结果是否相关？             | 最严格的首位命中率，反映检索器能否一次命中。              | **高**                    |     |
| **Hit@3**              | 检索器效果 | 检索器      | 前3个结果中是否有相关文档？          | 宽松的首位命中，常用于用户体验（用户会看前几个）。           | **中**                    |     |
| **Hit@5**              | 检索器效果 | 检索器      | 前5个结果中是否有相关文档？          | 更宽松，用于诊断检索器是否完全失败。                  | **中**                    |     |
| **MRR**                | 检索器效果 | 检索器      | 第一个正确答案平均排第几？           | 综合排名质量，对首个答案位置敏感。                   | **高**                    |     |
| **Recall@K** (K=5或10)  | 检索器效果 | 检索器      | 所有相关文档中被检索出的比例？         | 衡量检索器“找回”信息的能力，对生成答案覆盖度关键。          | **高**                    |     |
| **NDCG@K**             | 检索器效果 | 检索器      | 排序质量（考虑相关度等级）？          | 需要多级相关标签，RAG 中通常只用二值相关，所以不如 MRR 直接。 | **低**                    |     |
| **Context Precision**  | 上下文质量 | 检索器+相关性  | 检索到的块中相关块占比（排序加权）？      | 衡量上下文纯净度，噪音少则生成更可靠。                 | **高**                    |     |
| **Context Recall**     | 上下文质量 | 检索器+覆盖度  | 答案所需信息被检索覆盖多少？          | 直接关联答案完整性，重要。                       | **高**                    |     |
| **Context Relevancy**  | 上下文质量 | 检索器+相关性  | 检索块与问题的相关程度（不分排名）？      | 与 Context Precision 高度重叠，通常可被前者替代。  | **低**                    |     |
| **Faithfulness**       | 生成质量  | 生成器      | 答案是否基于检索上下文（不幻觉）？       | RAG 最关键的生成指标，无 ground truth 也能评估。   | **高**                    |     |
| **Answer Relevancy**   | 生成质量  | 生成器      | 答案与问题相关程度？              | 防止答案答非所问，但若检索相关则生成通常相关。             | **中**                    |     |
| **Answer Correctness** | 生成质量  | 生成器+真实答案 | 答案与 ground truth 事实一致性？ | 需要标注好的标准答案，成本高，但最权威。                | **中**（有真值时高）             |     |
| **Latency (P50/P99)**  | 系统性能  | 端到端系统    | 端到端响应耗时？                | 生产环境核心指标，离线评估时通常不测。                 | **高**（生产）<br>**低**（离线实验） |     |

### 重要度调整说明

1. **Hit@1 / MRR / Recall@K** 保持 **高**：它们直接决定检索器能否把最关键信息前置或完整找回。
2. **Hit@3 / Hit@5** 降为 **中**：因为 MRR 和 Recall@K 已经能更精细地反映排名和覆盖，且 Hit@K 区分度不够。
3. **NDCG@K** 降为 **低**：RAG 中相关度多是二值（相关/不相关），此时 NDCG 等价于召回率加排序折扣，不如直接用 MRR。
4. **Context Relevancy** 降为 **低**：和 Context Precision 概念重叠，且后者考虑排序，更实用。
5. **Faithfulness** 保持 **高**：这是 RAG 对抗幻觉的核心指标，无需真值。
6. **Answer Relevancy** 降为 **中**：如果检索和生成都正常，此指标通常不低；可作为辅助诊断。
7. **Answer Correctness** 定为 **中**（若有真值可提升为高）：因为需要标注答案，成本高，但在基准测试中重要。
8. **Latency** 分情况：**高**（生产监控），**低**（离线研究/学术实验）。

---

### 最终建议的“核心RAG指标集”（必选）

- **检索**：MRR，Recall@K (K=5或10)
- **上下文**：Context Recall，Context Precision
- **生成**：Faithfulness
- **性能**：Latency（上线后）
