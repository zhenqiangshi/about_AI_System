**流程分析：v3 (April 2026) 长期记忆/事实管理流水线**

![](../Images/Pasted%20image%2020260914151456.png)

这是一个面向**对话长期记忆**的简化高效架构，核心目标是从对话中提取事实、持久化存储，并在需要时精准检索。整体设计强调**简单、可扩展、冲突可解析**。

### 流程逐步拆解

1. **Dialogue（输入）**  
   原始多轮对话作为起点。

2. **1× LLM extract (single pass)**  
   - 只用**一次** LLM 调用，从整段对话中抽取结构化事实。  
   - “Single pass” 表示不进行多轮反思、验证或迭代抽取，追求低延迟和低成本。  
   - 优点：计算开销小、实现简单。  
   - 潜在风险：单次抽取可能漏掉细微信息或产生幻觉事实，依赖 LLM 的抽取质量。

3. **ADD-only store (preserve history)**  
   - **只增不减**的存储策略：新提取的事实只追加，从不删除或覆盖旧事实。  
   - 完整保留历史版本，为后续冲突解决提供完整上下文。  
   - 这是该架构的关键设计选择——用“冗余存储 + 检索时消解”代替“写入时去重/更新”。

4. **Hybrid retrieval (semantic · BM25 · entity · time)**  
   混合检索，融合四种信号：
   - **Semantic**：向量相似度（语义理解）
   - **BM25**：关键词匹配（精确词项）
   - **Entity**：实体对齐（人物、地点、事件等）
   - **Time**：时间信号（新旧、时间线顺序）

   多信号融合能同时兼顾语义相关性、字面匹配、实体一致性和时序关系。

5. **Top-k ranked facts**  
   最终输出排序后的 Top-k 事实，供下游 LLM 使用。

### 核心设计理念与优势

- **History is preserved; relevance and time resolve conflicts during retrieval**  
  这是整条流水线的哲学：  
  - 写入阶段极简（只 ADD），把复杂性全部推到检索阶段。  
  - 冲突（同一实体的新旧信息、矛盾陈述）不在存储时强制合并，而是在检索时通过**相关性 + 时间**动态消解。  
  - 好处：不会因为过早合并而丢失信息；时间信号天然能处理“最新优先”或“时间线推理”。

- **性能提升显著**  
  - LoCoMo：71.4 → 92.5（+21.1）  
  - LongMemEval：67.8 → 94.4（+26.6）  
  说明在长对话记忆评测上，这种“完整历史 + 混合检索 + 时间感知”的组合非常有效。

### 潜在优点总结
- 实现简单、成本可控（仅 1 次 LLM 抽取）。
- 历史完整，支持时间线和冲突回溯。
- 混合检索鲁棒性高，对语义、关键词、实体、时间都敏感。
- 扩展性好：存储只增，检索可独立优化。
