# 一、ES检索细节

## ES中的两阶段向量搜索差异

### 第一阶段：混合搜索中的向量搜索

python

编辑

```
# 第一阶段使用FusionExpr
fusionExpr = FusionExpr("weighted_sum", topk, {"weights": "0.05,0.95"})
matchExprs = [matchText, matchDense, fusionExpr]
```

**特点**：

- **近似搜索**：ES可能使用近似算法（如HNSW、IVF等）加速向量搜索
- **粗粒度排序**：与其他搜索方式（全文搜索）融合打分
- **批处理优化**：一次处理大量候选文档
- **混合评分**：关键词匹配得分 + 向量相似度得分

### 第二阶段：精确KNN搜索

python

编辑

```
# 第二阶段专门的向量相似度查询
matchDense = MatchDenseExpr(
    f"q_{dim}_vec",
    sres.query_vector,
    "float",
    "cosine",
    len(sres.ids),  # 仅对候选ID进行搜索
    {"similarity": 0.0},  # 相似度阈值设为0，获取所有候选
)
```

**特点**：

- **精确计算**：计算真正的余弦相似度分数
- **小规模计算**：仅针对第一阶段选出的候选文档
- **独立评分**：纯粹的向量相似度，不受其他因素影响
- **高质量分数**：用于后续的精确重排序

## 为什么需要两阶段？

### 1. **搜索精度 vs 性能的平衡**

- 第一阶段：快速筛选 + 近似向量匹配
- 第二阶段：精确向量相似度计算

### 2. **融合策略的不同**

- 第一阶段：向量搜索结果与全文搜索结果融合
- 第二阶段：纯向量相似度，用于加权融合

### 3. **资源利用优化**

文本

编辑

```
第一阶段: 100万文档 → 64个候选 (使用近似算法)
第二阶段: 仅对64个候选计算精确相似度 (精确算法)
```

## 实际工作流程

1. **第一阶段**：
    
    - 同时执行全文搜索和近似向量搜索
    - 使用加权融合得到初步排名
    - 返回Top-K候选文档
2. **第二阶段**：
    
    - 基于第一阶段的候选ID列表
    - 对这些文档计算精确的余弦相似度
    - 获取纯净的向量相似度分数
3. **最终融合**：
    
    - 将精确向量相似度与关键词相似度按权重融合
    - 生成最终排名

这样设计既保证了搜索的全面性（通过融合全文搜索），又保证了向量匹配的精确性（通过第二阶段的精确计算），是一种兼顾性能和准确性的优化策略。
